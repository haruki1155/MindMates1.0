## Staging test plan (synthetic students only; needs one tester mailbox you can read)
1. Import one synthetic roster row with the tester email. A second row with **no** email.
2. Request a login for an **unknown** ID, the **no-email** ID and the real ID: all three show the same message; only the real one gets mail.
3. The email arrives at the roster address only (not at anything typed in the app). Sign in with Student ID + temporary password.
4. Change password screen appears and cannot be skipped (kill and reopen the app: still there). Weak, reused-temporary and mismatched passwords are refused.
5. Save a good password: lands on Student Information, then Home after saving. Sign out; sign in with the permanent password.
6. Request a login again for the same ID: no email, password unchanged. Forgot password: link arrives at the roster email.
7. While on the temporary password, a direct call to a gated callable (for example mood or appointments) is refused with `first-login-pending`.
8. Regression: an employee sign-in, the existing QA students (QA-2026-0001/0002/0003) sign in as before.
9. Read-only checks: one UID, alias, reservation, roster link and verified recovery contact for the new student; issuance record holds no plain password.
10. Expiry (24 h) is checked on the next day by trying the old temporary password on a second synthetic row.
